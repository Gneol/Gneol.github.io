what is gneol?

Everything in Gneol starts with a file.

Gneol is the .gneol file.

A .gneol file is a plain-text program that declares an AI agent: its model, its subagents, its triggers, its tools, and its MCP servers. No glue code. No config sprawl.

Deploy the file, and Gneol turns it into a living agent. Scheduled triggers fire on time. Events fire workflows. Subagents take on focused tasks.

One binary reads the file, runs the agent, and drops you into a terminal to talk to it.

agent.gneol 
// an agent, in one file
program("Support Agent")
  .model("fast-llm")

model("fast-llm")
  .provider("openrouter")
  .modelId("openai/gpt-4o-mini")
  .apiKey("OPENROUTER_API_KEY")

subagent("Marcus")
  .description("Watches CI pipelines")

at("every:10min")
  .if("Backend health endpoint responds 200")
  .do("Run health probe")

getting started

Install the single binary, then deploy your first agent from a .gneol file — no server, no database.

bash — your first agent 
$ curl -sSL https://raw.githubusercontent.com/Gneol/Gneol/main/install.sh | bash
✓ Gneol installed → /usr/local/bin/gneol

$ cat > hello.gneol <<EOF
program("Hello World")
  .model("fast-llm")
EOF

$ gneol deploy -f hello.gneol
✓ Deployed. Agent "Hello World" is live.

everything in one place

Single Binary

CLI, LLM runtime, and terminal in one self-contained executable. Just download and run.

File-Driven Agents

Declare agents, models, triggers, tools, and MCP servers in a single .gneol file.

Automated Triggers

Time-based and event-based triggers fire your workflows automatically, guarded by LLM-evaluated conditions.

MCP & Custom Tools

Connect MCP servers or write custom tool scripts with gneol-sdk. Extend agents however you need.

Safe by Default

File permission metadata, .bak backups, and sentinel-based task management for long-running operations.

macOS & Linux

Precompiled binaries for macOS arm64 and Linux x64. One install command gets you going.

$ gneol --version # v1.0.0
